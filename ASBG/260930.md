## ASBG 2주차 Session 발표

### AWS Kiro - 프롬프트만으로 논문 투고 해보기
**Human-in-the-Loop Auto Research**

AWS Kiro와 ChatGPT를 활용하여 연구 주제 선정부터 실험 구현, 결과 분석, Figure 제작, LaTeX 논문 작성까지 연구 프로세스를 Agent 중심으로 진행해 본 경험을 발표했다.

---

### 1. AWS Kiro

Kiro는 AWS에서 VS Code를 기반으로 만든 Agent 기반 IDE로, 자연어 요구사항을 바로 코드로 구현하기보다 개발 과정을 명세화한 뒤 구현하는 **Spec-driven Development** 방식을 사용한다.

기본적으로 다음과 같은 흐름으로 작업을 구조화한다.

> Requirements → Design → Tasks

이를 통해 복잡하거나 장기간 진행되는 작업에서도 AI가 프로젝트의 목적과 제약을 지속적으로 참고하면서 구현할 수 있도록 한다.

주요 기능은 다음과 같다.

- **Specs**
  - 자연어 요구사항을 Requirements → Design → Tasks 단계로 구조화
- **Agent Hooks**
  - 파일 저장 등의 특정 이벤트가 발생했을 때 테스트·문서화·코드 검사 등을 자동 실행
- **Agent Steering & Skills**
  - Agent가 따라야 할 프로젝트 규칙과 반복 가능한 작업 절차 정의
- **MCP Servers**
  - GitHub, Jira, DB 등의 외부 도구 및 데이터 소스와 연결
- **Powers**
  - 특정 기술에 필요한 도구·지식·작업 절차를 하나의 패키지로 설치하여 필요한 상황에서 활용

---

### 2. 프로젝트를 시작한 계기

최근에는 AI가 단순한 질문 응답이나 코드 작성을 넘어 **연구 프로세스 자체를 자동화하고 가속화하려는 시도**가 등장하고 있다.

예를 들어,

- GPT를 활용한 수학 문제 해결 사례
- Andrej Karpathy의 **AutoResearch**
  - 가설 생성 → 코드 수정 → 실험 → 평가 과정 자동화
- Codex 등을 활용한 연구 실험 가속화

등을 보면서 AI를 과제나 학습 보조 도구로만 사용하는 것보다 실제 연구 과정에 적용해 보고 싶다는 생각이 들었다.

마침 대학생 AWS 기술 커뮤니티인 **START AWS**를 통해 Kiro Power를 지원받게 되어, 이를 활용해 하나의 연구 프로젝트를 처음부터 끝까지 진행해 보기로 했다.

---

### 3. 연구 주제

연구 주제는 다음과 같이 설정했다.

> **딥러닝 최적화 과정에서 Gradient Descent 대신 Newton Method를 활용하면 어떨까?**

Newton Method는 2차 미분 정보인 Hessian을 활용하여 빠르게 최적점으로 접근할 수 있지만, 계산 비용이 매우 크기 때문에 일반적인 딥러닝 최적화에서는 잘 사용되지 않는다.

이번 프로젝트에서는 해당 문제를 기반으로 실험을 구성하고, 최종적으로 **ArXiv Submission을 시도하는 것**을 목표로 했다.

---

### 4. Research Workflow

프로젝트에서는 사람의 직접적인 개입을 가능한 한 줄이고 다음과 같은 구조로 연구를 진행했다.

1. **ChatGPT**
   - 연구 방향 설정
   - 실험 결과 분석
   - 다음 실험 방향 제안

2. **Kiro**
   - ChatGPT가 제안한 실험 구현
   - 반복 실험 수행
   - 결과 정리
   - Figure 제작
   - GitHub Repository 관리
   - LaTeX 논문 작성 및 빌드

3. **반복**
   - Kiro의 실험 결과를 다시 ChatGPT에 전달
   - ChatGPT가 결과를 분석하고 다음 실험을 제안
   - Kiro가 다시 구현

즉,

> **ChatGPT가 연구 방향을 잡고, Kiro가 이를 실행하는 구조**

로 Research Workflow를 구성했다.

---

### 5. 실제 진행 규모

주요 실험은 약 **7일간(8/1 ~ 8/7)** 진행했다.

- 사용한 Kiro Credit: 약 **6,000 Credits**
- Kiro 요금 기준 약 **$120 상당**
- 실험·LaTeX 작성·재현 환경 구축 과정에서 총 **306 Commit**

짧은 기간 동안 Agent가 반복적인 구현과 실험을 지속적으로 수행하게 하면서 비교적 많은 작업을 진행할 수 있었다.

### 7. ArXiv Submission 시도

완성된 결과물을 학술적인 기록으로 남기기 위해 **ArXiv Submission**을 시도했다.

하지만 ArXiv Endorsement를 받지 못해 최종 Submission에는 실패했다.

이후 연구와 밀접한 분야의 해외 연구자 3명에게 Cold Mail을 보내 직접 Endorsement를 요청했다.

한 연구자로부터 연구 주제 자체에 대해서는 긍정적인 피드백을 받을 수 있었지만,

> **"too AI-generated"**

되어 보인다는 평가와 함께, 최근 이러한 형태의 논문으로 인해 연구 커뮤니티에 혼란이 많다는 이유로 Endorsement를 받지는 못했다.

### 8. Auto Research를 진행하며 느낀 한계

처음에는 사람의 개입을 최소화하는 것을 프로젝트의 목표 중 하나로 두었다.

하지만 실험을 계속 진행하면서 어느 순간부터는 내가 Kiro와 ChatGPT가 제안하는 내용을 충분히 이해하지 못한 상태에서 Agent가 요청하는 권한을 승인하는 역할만 수행하고 있었다.

결과적으로

- 25페이지의 Paper
- 재현 가능한 실험 코드
- 공개 Repository
- Figure
- LaTeX 문서

까지 만들어졌지만, 연구자가 연구 과정과 결과를 충분히 이해하지 못한다면 결과물의 형식적인 완성도만으로는 온전한 연구라고 보기 어렵다는 점을 경험했다.

특히 기존 Workflow에는 중요한 단계가 하나 빠져 있었다.

> **내가 연구 결과를 직접 이해하고 검증하는 단계가 없었다.**

### 9. Human-in-the-Loop Auto Research

이번 프로젝트를 통해 AI와 사람이 연구 과정에서 잘할 수 있는 역할이 다르다는 점을 느꼈다.

#### AI가 잘했던 것

- 코드 구현
- 반복 실험
- Figure 제작
- LaTeX 작성
- GitHub Repository 관리
- 반복적인 실험 결과 정리

#### 사람이 해야 했던 것

- 결과가 왜 나왔는지 이해하기
- 실험 과정과 결과 검증하기
- 결과의 의미 해석하기
- 연구의 주장과 한계를 판단하기
- 결과물을 자신의 언어로 설명하고 글로 남기기

따라서 연구 자동화의 핵심은 연구 과정에서 사람을 완전히 제거하는 것이 아니라,

> **AI가 반복적인 실행을 담당하고, 사람이 이해·검증·해석의 Loop 안에 계속 존재하도록 만드는 것**

이라고 생각하게 되었다.

### 10. AWS Kiro 사용 후기

#### 좋은 점

- 최신 Frontier Model을 선택하여 작업 가능
- 긴 작업을 비교적 끊김 없이 진행 가능
- Spec을 통해 프로젝트의 목적과 제약을 지속적으로 유지 가능
- 한 달치 Credit을 한 번에 지급받기 때문에 복잡한 프로젝트를 장시간 진행하기 용이

#### 아쉬운 점

- Windows PowerShell 명령 처리의 불안정성
- 잘못된 Shell Command로 인해 Session이 중단되는 경우 존재
- 반복적인 Approval 요구
- 완전히 작업을 맡겨 놓기보다는 Session이 중단되지 않았는지 중간중간 확인해야 함

전체적으로 다양한 Frontier Model과 충분한 Credit을 활용하여 장시간 Agent 작업을 진행하기에는 유용했지만, **Session 안정성과 완전한 자동 실행 측면에서는 아직 개선될 부분이 있었다.**

---

### Takeaway

이번 프로젝트의 목표는 처음에는 **"AI에게 연구를 어디까지 맡길 수 있을까?"**를 직접 실험해 보는 것이었다.

실제로 Agent를 활용하면 짧은 기간에도 코드 구현, 반복 실험, Figure 제작, LaTeX 논문 작성과 같은 작업을 상당 부분 자동화할 수 있었다.

하지만 직접 연구 과정을 진행해 본 결과, 더 중요한 질문은

> **"AI가 연구자를 대체할 수 있는가?"**

보다는

> **"AI에게 실행을 맡기면서도 연구자가 어떻게 연구의 이해·검증·해석 과정에 계속 남아 있을 것인가?"**

에 가까웠다.

결국 Auto Research에서 중요한 것은 사람을 Workflow에서 제거하는 것이 아니라,  
**사람이 어떤 지점에서 반드시 Loop 안에 존재해야 하는지를 설계하는 것**이라고 느꼈다.

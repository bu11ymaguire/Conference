## ASBG 2주차 Session 발표

### AWS Kiro - 프롬프트만으로 논문 투고 해보기
**Human-in-the-Loop Auto Research**

AWS Kiro를 활용해 연구 주제 선정부터 실험 구현, 결과 분석, Figure 제작, LaTeX 논문 작성까지 연구 프로세스를 에이전트 중심으로 진행해 본 경험을 발표했다.

### AWS Kiro

Kiro는 AWS에서 VS Code를 기반으로 만든 에이전트 기반 IDE로, 자연어 요구사항을 바로 코드로 구현하기보다 다음과 같이 개발 과정을 명세화하는 **Spec-driven Development** 방식을 사용한다.

- Requirements
- Design
- Tasks

이를 통해 장기간의 작업에서도 AI가 프로젝트의 목적과 제약을 지속적으로 참고하면서 구현을 진행할 수 있다.

주요 기능으로는 다음과 같은 것들이 있다.

- **Specs**: 요구사항 → 설계 → 구현 작업을 문서화
- **Agent Hooks**: 특정 이벤트 발생 시 테스트·문서화 등의 작업 자동 실행
- **Agent Steering & Skills**: 프로젝트 규칙과 반복 작업 절차 정의
- **MCP Servers**: GitHub, Jira, DB 등 외부 도구 및 데이터 연결
- **Powers**: 특정 기술의 도구·지식·작업 절차를 패키지 형태로 제공

### 프로젝트를 시작한 계기

최근에는 AI가 단순히 질문에 답하거나 코드를 작성하는 수준을 넘어 연구 과정 자체를 자동화·가속화하려는 시도가 등장하고 있다.

예를 들어,

- AI를 활용해 기존 수학 문제를 해결하는 사례
- Andrej Karpathy의 **AutoResearch**
- Codex를 활용해 연구자가 더 많은 실험을 수행하도록 지원하는 연구 환경

등을 보면서 AI를 과제나 학습 보조에만 사용하는 것보다 실제 연구 프로세스에 적용해 보고 싶다는 생각이 들었다.

마침 START AWS를 통해 Kiro Power를 지원받게 되어 이를 활용해 하나의 연구 프로젝트를 끝까지 진행해 보기로 했다.

### Research Workflow

연구 주제는 다음과 같이 설정했다.

> 딥러닝 최적화 과정에서 Gradient Descent 대신 Newton Method를 활용할 수 있을까?

Newton Method는 Hessian 계산 등으로 인해 연산량이 매우 크기 때문에 일반적인 딥러닝 최적화에서는 잘 사용되지 않는다.

이번 프로젝트에서는 사람의 직접적인 개입을 가능한 한 줄이고,

1. ChatGPT가 연구 방향과 다음 실험을 제안하고
2. Kiro가 이를 코드로 구현하고
3. 실험 결과를 다시 ChatGPT가 분석하고
4. 다음 실험 방향을 Kiro에게 전달하는

형태의 반복적인 Research Workflow를 구성했다.

이 과정에서 Kiro는

- 실험 코드 구현
- 반복 실험
- 결과 분석용 Figure 제작
- LaTeX 논문 작성
- GitHub Repository 관리

등을 수행했다.

### Input

실제 연구 과정에서 투입된 자원은 다음과 같다.

- 주요 실험 기간: **7일 (8/1 ~ 8/7)**
- Kiro Credit: 약 **6,000 Credits**
- 실험 및 논문 제작 과정에서 **306번의 Commit**

### Output

짧은 기간 동안 에이전트를 활용해 다음과 같은 결과물을 만들 수 있었다.

- LaTeX로 작성된 **25페이지 Paper**
- 실험 재현을 위한 공개 Repository
- 총 **2개의 Repository / 5개의 Branch**
- 실험 코드
- Figure 및 결과 분석 자료
- LaTeX Source

즉, 구현과 반복 실험처럼 시간이 많이 필요한 작업은 AI Agent를 활용해 상당 부분 자동화할 수 있었다.

### ArXiv Submission 시도

완성된 결과물을 학술적인 기록으로 남기기 위해 ArXiv Submission을 시도했지만, Endorsement를 받지 못해 최종 제출에는 실패했다.

이후 연구 분야와 관련된 해외 연구자들에게 직접 Endorsement를 요청했고, 한 연구자로부터 연구 주제 자체에 대해서는 긍정적인 피드백을 받을 수 있었다.

하지만 동시에 논문이

> "too AI-generated"

되어 보인다는 평가를 받았고, 이러한 형태의 논문이 증가하면서 연구 커뮤니티에 혼란이 발생하고 있다는 이유로 Endorsement를 받지는 못했다.

### 프로젝트를 통해 느낀 점

처음에는 연구자의 개입을 최소화하는 것을 목표로 Workflow를 설계했다.

하지만 실험을 반복하면서 어느 순간부터는 내가 결과를 충분히 이해하지 못한 상태에서 GPT와 Kiro가 제안하는 내용을 확인하고 승인하는 역할만 수행하고 있었다.

결과적으로

- 25페이지의 Paper
- 재현 가능한 실험 코드
- 공개 Repository
- Figure와 실험 결과

까지 만들어졌음에도 불구하고, 연구자가 연구 내용을 충분히 이해하고 설명하지 못한다면 그것을 온전히 자신의 연구라고 하기 어렵다는 점을 경험했다.

특히 기존 Workflow에는

> **연구자가 결과를 직접 이해하고 검증하는 단계가 빠져 있었다.**

### Human-in-the-Loop Auto Research

이번 프로젝트를 통해 AI와 사람이 연구 과정에서 담당해야 할 역할을 다음과 같이 생각해 볼 수 있었다.

**AI가 잘했던 것**

- 구현
- 반복 실험
- Figure 제작
- LaTeX 작성
- Repository 관리

**사람이 해야 하는 것**

- 결과가 왜 나왔는지 이해하기
- 실험 결과를 검증하기
- 결과의 의미를 해석하기
- 연구의 주장과 한계를 결정하기
- 이를 자신의 언어로 글로 작성하기

따라서 연구 자동화의 핵심은 사람을 연구 과정에서 제거하는 것이 아니라,

> **AI가 반복적인 실행을 담당하고, 사람이 이해·검증·해석의 Loop 안에 계속 존재하도록 만드는 것**

이라고 생각하게 되었다.

### Kiro 사용 후기

Kiro의 장점은 최신 프론티어 모델을 선택해 비교적 긴 작업을 이어갈 수 있고, Spec을 기반으로 복잡한 프로젝트의 맥락을 유지하기 좋다는 점이었다.

반면 실제 장시간 Agent 작업에서는

- Windows PowerShell 명령 처리의 불안정성
- 세션 중단
- 반복적인 Approval 요구

등으로 인해 완전히 작업을 맡겨 놓기에는 아직 불편한 부분도 있었다.

전체적으로는 다양한 모델 선택지와 충분한 Credit을 활용해 장시간 작업을 수행하기에는 유용했지만, 세션 안정성과 자동 실행 측면에서는 개선될 부분이 있다고 느꼈다.
